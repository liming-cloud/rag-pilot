# 客户部署清单（全新安装）

给第一次在客户服务器上安装的人用：按顺序逐项打勾。命令和每一项的含义以[运维手册](../../deploy/README.md)为准，这里只列要准备什么、做到哪一步算完成。部署记录写在 #129（只写汇总结果，不写客户名称、服务器地址、账号和密码）。

## 一、部署前（提前一两天，和客户运维一起确认）

- [ ] **服务器**：Linux（x86_64 或 arm64），至少 4 核 CPU、9 GB 内存（其中 ocr 容器约占 1 GB），磁盘 100 GB 以上；备份最好放在单独的磁盘上（`.env` 里的 `RAG_BACKUP_DIR`）。
- [ ] **软件**：Docker 24 以上，带 Compose 插件（`docker compose version` 能输出版本）；有 `curl`、`sha256sum`；运维账号能直接执行 `docker` 命令。
- [ ] **外网**：安装时能访问下面这些地址，访问不了的提前配好镜像源：
  - Docker Hub，或者镜像源、内网仓库（对应 `.env` 里的 `RAG_DB_IMAGE` 等 5 项，摘要不变）；
  - PyPI，或者镜像源（`RAG_PIP_INDEX_URL`，如 `https://mirrors.aliyun.com/pypi/simple`）；
  - `modelscope.cn`：构建 ocr 镜像时下载识别模型；
  - 模型服务：默认 `https://api.siliconflow.cn`，自建的就填 `MODEL_BASE_URL`。服务一直运行期间都要能访问。
- [ ] **端口**：员工访问用 `WEB_PORT`（默认 80），只开给内网；`APP_PORT`（默认 8080）只绑本机，用于运维检查。
- [ ] **模型**：服务商密钥（`MODEL_API_KEY`）已开通，额度够用；不用硅基流动时，确认嵌入、重排、对话三个模型的名字（嵌入模型装好后不能再改）。
- [ ] **客户要定的**：品牌名和登录提示（`RAG_BRAND_*`）、超级管理员账号名、统计时区、提问限额（每人每分钟 10 次、每天 300 次，可调）。
- [ ] **资料**：第一批要导入的资料已经整理好（单个文件不超过 50 MB；旧版 `.doc`、`.ppt` 先另存为 `.docx`、`.pptx`）。
- [ ] **安装包**：从 Release 下载 `rag-pilot-1.1.0.1.tar.gz` 和 `.SHA256SUMS`，带到现场或者在服务器上下载。

## 二、部署当天

- [ ] 校验并解压安装包（运维手册“三、安装”）。复制 `.env.example` 为 `.env`，权限设成 600，填好必填项：
  - `DB_PASSWORD`、`REDIS_PASSWORD`：用 `openssl rand -hex 24` 生成；
  - `MODEL_API_KEY`；
  - `RAG_ADMIN_PASSWORD`；
  - `RAG_MASTER_KEY`：用 `openssl rand -base64 32` 生成，**抄一份交给客户妥善保管**（见运维手册“七、主密钥”）。
- [ ] 运行 `./install.sh`。第一次会构建 ocr 镜像，要下载约 700 MB。看到“部署验证通过”就装好了，其中“图片文字识别服务”这一项也要通过。
- [ ] 浏览器打开 `http://<服务器地址>:<WEB_PORT>`，用超级管理员登录。改了密码以后，再跑 `verify.sh` 要用环境变量 `VERIFY_ADMIN_PASSWORD` 传新密码。
- [ ] 管理端“模型管理”：对话、重排、嵌入三项的连通测试都通过。
- [ ] 建一个试用知识库，上传一份带截图的资料和一份纯文字资料，等状态变成“可用”。员工端问一个答案在截图里的问题，回答带出处，点开引用能看到原文。
- [ ] 建一个员工角色和测试账号，只授权这一个知识库；用测试账号确认看不到其他知识库，问其他库的内容会回答“找不到”。
- [ ] 运行一次 `./backup.sh`，确认备份目录里有文件。再演练一次恢复：`./restore.sh <备份目录>`，输入 yes，然后跑 `./verify.sh`。**只在没有正式数据之前演练。**
- [ ] 配置每日自动备份（运维手册“五、备份与恢复”里的 crontab）。
- [ ] 在 #129 记下各步骤的结果、耗时和遇到的问题，把手工演练这一项勾掉。

## 三、常见卡点

| 现象 | 处理 |
| --- | --- |
| 拉镜像或者 `pip install` 超时 | 换镜像源（第一节的“外网”），再运行一次 `./build.sh` |
| 模型连通测试 401 / 403 | 密钥不对，或者没开通这个模型 |
| 上传后长时间“解析中”，日志里有 `event=embedding_rate_limited` | 服务商限流：调小 `RAG_INGESTION_CONCURRENCY`，或者提高额度 |
| 截图里的内容问不到，日志里有 `event=ocr_unavailable` | `docker compose logs ocr` 看原因；恢复后 10 分钟内会自动补上 |
| 文件超过 50 MB 被拒 | 压缩课件里的图片，或者另存为 PDF 后再上传 |

更多见运维手册“九、常见故障”。

## 四、上线之后

- 第一周每天看一次运营概览和知识缺口，把员工问不到的问题交给总部补资料。
- 用管理端“知识质量”建一个题集，放进客户确认过的标准题，导入资料后跑一次；以后换模型、改资料都跑一次，和上一次对比。结论记在 #134。
- 发现的问题每个开一个 Issue，写清楚复现步骤，链接到 #174 的队列里。
- 需要回退时，按运维手册“六、升级与回退”用备份恢复。全新安装没有旧版本，出问题直接按 Issue 修复后再升级。
