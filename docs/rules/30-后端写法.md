# 后端写法规则（B）

持久层、配置、时间、编译、审计、日志、登录、迁移。卡片格式见 [索引](00-索引.md)。

## B-01 MyBatis-Plus 经 rag-persistence

规则：MyBatis-Plus 经平台组件 rag-persistence 引入，全局配置（Mapper XML 位置、分页插件）和分页转换 `Pages`（`persistence.paging`）都在那里，上下文不自己声明 MyBatis-Plus（D-053）。它的 DO、Wrapper、Page 只出现在 infrastructure 包和 rag-persistence；查询结果映射到 infrastructure 里只有字段的 `XxxDO`，不用 `Map` 加强转（`bigint[]` 列在 `resultMap` 里指定 `ArrayTypeHandler`）；不引入 MapStruct，不做多层 DTO 转换。
理由：持久层框架不泄漏到业务层。
状态：生效
检查：自动[ArchitectureRulesTest]（`MYBATIS_ONLY_IN_INFRASTRUCTURE`、`DO_ONLY_IN_INFRASTRUCTURE`；不用 Map 强转靠评审）

## B-02 SQL 只写在 Mapper XML

规则：SQL 只写在 Mapper XML（`src/main/resources/mapper/<模块名>/<Mapper 名>.xml`）里；不用 `@Select` 等 SQL 注解，条件构造器不拼原始 SQL（`apply`、`last`、`inSql`、`setSql` 等）；SQL 里不取数据库的当前时间（`now()` 等），时间由 `Clock` 传入。单表的增删改查、存在判断、计数和分页用 `BaseMapper` 加 `LambdaQueryWrapper`/`LambdaUpdateWrapper`，一张表一个 Mapper；XML 只写 upsert、多行插入、多表、聚合、递归和检索（D-053）。
理由：SQL 与 Java 分开评审；时间可由测试固定。
状态：生效
检查：自动[ArchitectureRulesTest、MapperXmlLayoutTest]（`NO_SQL_ANNOTATIONS`、`NO_RAW_SQL_IN_WRAPPER`；不取数据库当前时间靠评审）

## B-03 配置只用 @ConfigurationProperties

规则：配置只通过各模块的 `@ConfigurationProperties` record 读取（如 `AnsweringProperties`），取值在构造时校验，非法配置启动失败；不用 `@Value`。
理由：配置集中、启动即校验。
状态：生效
检查：自动[ArchitectureRulesTest]（`NO_VALUE_INJECTION`；构造时校验靠评审）

## B-04 当前时间用 Clock

规则：要当前时间的类注入 rag-app 声明的 `Clock`（UTC），不直接调用 `now()`，测试传固定时钟。
理由：时间可测。
状态：生效
检查：评审

## B-05 编译告警与空值声明

规则：编译开 `-Xlint:all -Werror`，有告警构建就失败；确实要留的用 `@SuppressWarnings` 写在最小范围并注明原因（测试里读 JSON 的 `unchecked`、`rawtypes` 按方法抑制）。每个主代码包的 `package-info.java` 标 JSpecify 的 `@NullMarked`，可以为 null 的参数、返回值、字段写 `@Nullable`（包装类型的参数和 record 组件都表示可空），MyBatis 的 `XxxDO` 标 `@NullUnmarked`（D-052）。
理由：编译器和空值注解能提前发现一类错误。
状态：生效
检查：自动[PackageLayoutTest]（`everyPackageIsNullMarked`；零告警由编译参数 `-Werror` 保证，#199）

## B-06 管理操作写审计

规则：管理操作（授权、角色和权限点、账号、删除和替换资料、系统设置）在应用服务里、操作成功之后经 identity 的 `AuditTrail` 记一条审计，和操作同一个事务（D-052）；说明里不写密码、密钥。
理由：管理操作可追溯。
状态：生效
检查：测试（`AuditTrailCoverageTests`、`AuditTrailTests`）

## B-07 运维事件日志

规则：每条日志都是一行字面量 `event=<snake_case 名字> 键=值`（键用英文，不写中文自由文本、不拼接日志串），Logger 统一命名为 `log`；降级路径（模型失败后用固定回复、退回按原文分组等）至少记 warn。代码里的每个事件都列在运维手册 `deploy/README.md`；不记密码、密钥、提示词和员工的问题原文，用户输入的值先校验再写进日志。
理由：运维能按事件名检索，敏感内容不落日志。
状态：生效
检查：自动[LogFormatTest]（格式、命名、手册覆盖；不记敏感内容靠评审和 `ObservabilityTests`、`ModelCallFailureLogTest`）

## B-08 登录与权限只用 Sa-Token 注解

规则：登录和角色校验只用 Sa-Token 注解；登录会话和密码摘要经 identity 的端口 `Sessions`、`PasswordHasher`，application、domain 不依赖 Sa-Token。权限点由各上下文在自己的 `api` 包里声明（实现 identity 的 `PermissionCatalog`），identity 运行时汇总。
理由：鉴权方式唯一，业务层不依赖鉴权框架。
状态：生效
检查：自动[ArchitectureRulesTest、PackageLayoutTest]（`LOGIN_AND_ROLE_ONLY_BY_ANNOTATION`、`ENDPOINTS_NEED_PERMISSION`、`PERMISSIONS_IN_CATALOG`、`APPLICATION_NOT_ON_SA_TOKEN`）

## B-09 Flyway 迁移命名

规则：Flyway 迁移放在所属模块的 `db/migration/<模块名>/`，版本号用 `V<yyyyMMddNNNN>__说明.sql`。
理由：版本号全局不重复，位置可检查。
状态：生效
检查：自动[MigrationLayoutTest]

## B-10 方法复杂度

规则：生产代码的方法圈复杂度不超过 10、可执行语句不超过 30 条，由 Checkstyle 在 `./mvnw verify` 时检查（`backend/checkstyle.xml`，只开这两条，不开格式类规则；D-067）。超了就拆成命名清楚的步骤，不加例外；类的行数只作参考。
理由：方法短、分支少才好读好测；靠评审数语句数不可靠。
状态：生效
检查：自动[ComplexityGateTest]（违规样例在 `archfixture/complexity`，证明两条规则会拦、正好在上限的放行）
