# 前端规则（F）

卡片格式见 [索引](00-索引.md)。

## F-01 界面只用 shadcn/ui

规则：界面只用 shadcn/ui 组件（`components/ui`：Button、Input、Label、NativeSelect、Checkbox、Table，缺的先按 shadcn 加进来）和 tokens.css 变量，feature 里不直接写 `<input>`、`<select>`、`<table>` 等原生元素；不做像素级调整。
理由：界面风格一致。
状态：生效
检查：自动[structure.test]

## F-02 新页面先做 MSW 原型

规则：新页面先做 MSW 假数据原型，确认后再接接口。
理由：先确认界面再接接口，避免返工（见 P-07）。
状态：生效
检查：评审

## F-03 前端目录结构

规则：`frontend/src` 下：`app/`：路由、布局；`components/ui/`：只放 shadcn 生成的组件；`lib/`：通用工具与请求封装；`mocks/`：MSW 假接口；`styles/`：`tokens.css`；`test/`：测试初始化。`features/<领域>/`：页面（`XxxPage.tsx`）、`api.ts`（接口调用和类型）、子组件，测试与源文件同目录。feature 之间只能引用对方的 `api.ts`，不引用 `app/`。
理由：feature 之间松耦合。
状态：生效
检查：自动[structure.test]

## F-04 前端写法

规则：（#145）查询键定义在各 feature 的 `api.ts`（`xxxKeys`），页面不现场写 `queryKey: [...]`；出错提示用 `lib/errors.tsx` 的 `ErrorMessage`（带 `role="alert"`）；判断权限用 `lib/permissions.tsx` 的 `PERMISSIONS` 常量；组件文件不超过 300 行，对话框、分区拆到同目录；复杂的交互逻辑抽成 hook 单独测试（如问答页的 `useConversationAsk`）。
理由：写法统一，便于检查和复用。
状态：生效
检查：自动[structure.test]（hook 单独测试靠评审）
