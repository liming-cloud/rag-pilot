#134 的决定：

- **数据不离开客户环境**：客户资料、问题、评测报告原文都在客户服务器（离线包部署）上导入、核对、标注和评测，代码仓库、CI、我们自己的机器上不放；Issue 和 PR 里只记汇总数字和脱敏后的问题类型。试点结束按客户要求删除。
- **模型服务**：客户 2026-11-05 答复允许资料片段发给外部模型服务，照常用默认服务（D-043）；评测报告注明所用模型。
- **指标**：真实评测集这一轮只建基线、不设硬目标，README 的目标值只适用于合成集；越权泄漏为 0 仍是硬要求。
- **解析核对**：`deploy/parse-check.sh` 运行 `deploy/parse-check.sql`，只读数据库里的 `document` 和 `chunk`，按文档给出分块数、标题层级（`heading_path` 的最深一级）、表格行（估计）、乱码和空白占比与结论。没有写成 Java 命令行或管理端页面：客户环境里只有部署包，不需要新增依赖、接口或权限点；`ParseCheckSqlTests` 用合成分块验证。不重新解析原始文件，看到的就是入库后检索实际用到的内容。
