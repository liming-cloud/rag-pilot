# D-071 资料体检的实施结论：入库时记信号、规则写成一段 SQL、阈值按试点资料校准（2026-11-13，#218）

按 D-069、D-070 实施资料体检时定下的做法和阈值。

- **信号在入库时记下，存进 `document` 的可空列**：读取时得到图片数（Word 按文档里的图片、PDF 按每页的图片对象、PowerPoint 按图片形状）和最大一张表格的数据行数；写分块时从分块算出字数、空白、乱码字符数和标题层级（口径同原 `parse-check.sql`）。迁移从已有分块回填后四项；图片数、表格行要重新入库才有，为空时相应规则不判断。
- **疑似重复存成文档对**（`document_overlap`）：一份文档去重后的分块正文有 ≥ 80% 在另一份里也有，按正文摘要比较，两个方向各算一次；入库写分块时重算，删除文档时级联删除。完全相同按文件摘要（`sha256`）在查询时比较。两种都只找查看人能访问的库（复用检索的授权片段，A-05），不提示无权访问的库里有没有副本。
- **规则只写在 `KnowledgeQueryMapper.xml` 的 `findings` 一段 SQL**：文档列表、“需整理”筛选和知识库列表的“需整理”份数共用；`deploy/parse-check.sql` 用同样的规则和名称（按全租户找重复），`ParseCheckSqlTests` 用阈值两侧的样例校验两边一致。没有写成 Java 规则：筛选和计数要在数据库里分页。
- **页面**：体检列只显示标签，点标签弹出整改建议和重复的文档；知识库列表加“需整理 N 份”，点进去带上筛选（人确认原型，2026-11-13）。弹出层用已有的对话框，没有新增 Popover 依赖。写操作（上传、新版本、重新处理、改有效期）的响应不带结论（`findings` 为 null），页面以列表为准。

| 结论 | 规则 | 依据 |
| --- | --- | --- |
| 疑似内容在图片里 | Word、PDF、PowerPoint，图片 ≥ 2 张且可见字数 < 200 × 图片数 | 试点资料：4 份截图为主的手册每张图 23～56 字（其中一份只有 2 张图），正常的长 Word、PDF 每张图 458～15735 字；10 份课件里 7 份每张图 7～164 字被标出，3 份 206～1732 字未标 |
| Word 没用标题样式 | .docx，标题层级 0，≥ 5 块 | 沿用原“未识别标题”的 5 块；试点 2 份 |
| PDF 读不出章节 | .pdf，标题层级 0，≥ 5 块 | PDF 解析不出标题，长 PDF 都会被标，提示改传 Word；试点 3 份 |
| 文档没有标题 | .txt、.md，标题层级 0，≥ 5 块 | 试点 6 份长文本 |
| 表格过大 | 最大一张表 ≥ 500 行 | 试点最大的两张表 11002、30032 行（#226 被限流的两份），其余 ≤ 257 行 |
| 疑似乱码 / 疑似版面散乱 | 乱码 ≥ 1% / 空白 ≥ 40% | 沿用原阈值；试点最高 0.31%、21.9%，都不触发 |
| 重复 / 疑似重复 | 文件摘要相同 / 分块正文 ≥ 80% 重合 | D-070 |

试点数字来自本机用新版读取器和分块器读一遍试点资料包（96 个可读文件，资料不出本机），只记汇总。
