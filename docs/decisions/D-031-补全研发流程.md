# D-031 借鉴 domain-forge 补全研发流程，约束改为自动检查（2026-10-29）

对照 domain-forge（DDD 微服务脚手架）的研发流程（#82），经人工确认：Issue 加 `status/needs-decision`／`status/ready`，未决问题开工前写进 Issue；AGENTS.md 加“先停下来问人”的清单、完成定义（没达到的验收不关 Issue，缺口经人同意拆成新 Issue）、合并规则（不叠放 PR、人读过后开 auto-merge、AI 不自己合并）、不稳定测试处理和评审清单。AGENTS.md 的约束能判定的写成测试：`ArchitectureRulesTest` 用 ArchUnit（`com.tngtech.archunit:archunit` 1.4.2，test 范围；Spring Modulith 2.1.0 本身就依赖这个版本，显式声明是为了不靠传递依赖），每条规则配一个违规样例；`MigrationLayoutTest` 检查迁移目录与版本号。另加 Dependabot（只提醒）、Actions 固定提交 SHA、`.editorconfig`。

不照搬的：切片 sub-issue（会回到碎片化）、`docs/` 文档体系和编号规则卡、每个组件一篇设计文档、独立的规则 Maven 模块和 Checkstyle、把 `eval` 设为必需检查（按路径触发、花钱）、度量标签。决策仍集中记在本文件；被取代的条目在标题注明，正文不改。
