# D-039 管理端列表按数据量设计：服务端分页筛选、弹窗表单、详情分标签（2026-10-30）

#115 第一版原型人工评审指出：知识库、用户、回答记录多了以后页面会失控，角色权限满屏勾选容易看错行。改为：列表一律服务端分页加筛选，请求 `page`（从 1 起）、`size`（默认 20，最多 100）和各页的筛选条件，响应 `{items, total, page, size}`；用户按关键词、角色、状态（启用、停用、锁定）筛，回答记录按类型、处理状态、时间（7/30/90 天、不限）、问题关键词筛，知识库按名称筛，文档按文件名、状态筛。新建和修改（新建账号、改角色、重置密码、新建知识库、添加授权、回答记录详情）都在弹窗里做，列表只放一行摘要。知识库改为列表加详情页，详情分“文档”“授权”两个标签；授权给账号时按关键词搜，最多列 10 个，不一次列出全部账号。角色默认只读，每个菜单一行、只列出已有的操作；点“编辑权限”后按钮权限是可点选的标签，选按钮自动勾上“可进入”，取消“可进入”时一起取消该菜单的按钮。导出评测题草稿导出当前筛选下的全部记录（最多 1000 条）。

接口相应调整：`GET /api/users`、`/api/answers`、`/api/knowledge-bases/page`、`/api/knowledge-bases/{id}/documents` 返回分页结构；回答记录带提问人 `askerName`，文档带被替换的文件名 `replacesFilename`，知识库授权账号列表带用户名和显示名；新增 `GET /api/knowledge-bases/{id}`。员工端选库仍用不分页的 `GET /api/knowledge-bases`（只含授权给自己的库）。评测等待文档入库处理完要翻页读取文档列表。新增前端依赖 `@radix-ui/react-dialog`（shadcn Dialog，#112 时已同意按需引入）。
