# D-062 问答编排与数据引用的实施结论：同一套引用编号、两种数据拒答原因、三道检查都在 rag-data（2026-11-09，#182）

落实 D-058、D-059（人对 #182 的三个未决问题全按推荐答复），实施中定的几点：

- **选工具**：answering 的 `DataLookup` 先取提问人能用的工具（客户 `tools/list` ∩ 授权 ∩ 部署配置 `rag.data.tools`）和能看的站点，交回答模型做一次受限调用，只要一个 JSON 对象 `{"tool":…,"arguments":{…}}`（提示词是 answering 的策略 `ToolSelectionPrompt`）。**没有可用工具时不调用模型**，现有问答的行为和耗时不变；部署没配置可授权的工具时连授权也不查，问答的 SQL 条数不变（`AskSqlBudgetTests`）；模型选了不在清单里的工具不调；选工具时模型不可用或输出不合格式，按不查数据处理，回答只依据资料。
- **三道检查都在 rag-data 的 `DataQueryService`**：调用前经 `DataScopeService`（判定仍只写一处）；令牌带放行的站点；返回后先校验结构（规范第 5 节的 `data/source/query/asOf/queriedAt/truncated`，不符合整份不用），再逐行核对 `store_id`，范围外的行和没有站点标识的行都丢弃。只校验我方要用的字段，不做完整的 JSON Schema 校验（要新增依赖，目前不需要）。answering 只经 rag-data 的 `api`（`DataQueries`）查数据。
- **引用编号**：查到的数据接在资料后面、同一套编号（资料 n 条时数据是 n+1），回答引用它才挂数据出处（`DataCitation`：工具、来源系统和数据集、查询条件、数据截至和查询时间、是否截断）。没有够分的资料但查到了数据，照样依据数据回答。数据出处存 `answer_data_citation`，只存出处不存数据。
- **失败如实说**：新增拒答原因 `DATA_DENIED`（范围外或没有工具授权，没发请求）、`DATA_UNAVAILABLE`（超时、401/403、429、工具报错、协议错误、格式不符）；资料答得上来时照常回答，末尾补一句“（数据部分：……）”，答不上来就按数据的原因拒答，话术是查询给的说明。工具自己报错时说明前加“数据暂时查不到：”。没有缓存，失败时不会用旧数据。
- **审计与日志**：每次调用（含被拒的）在 `audit_log` 记一条 `DATA_TOOL_CALLED`（保留 1 年，同管理操作审计），说明里有业务条件、范围摘要、行数、截断、丢弃行数、耗时、状态、令牌 `jti`，不记令牌、返回内容和问题原文；审计单独一个事务，远程调用不在事务里。日志 `event=tool_call` 不带用户和条件（事件见运维手册）。
- **修了 #180 的状态码判断**：`RecordingHttpClient` 只记 POST 的响应；SDK 握手后打开 SSE 流的 GET 被服务器回 405（规范允许）时，原来会覆盖状态码、把超时误判成协议错误而不重试（CI 上 `retriesTimeoutOnce` 偶发失败）。
- **没做的**（记进 ROADMAP 待办）：配了工具的部署每次提问要查一次授权（4 条带索引的查询）、调一次 `tools/list`，都没有缓存；规范第 6 节“每个连接并发 ≤ 8”没有单独限制（每用户每分钟的工具调用受提问限流 `RAG_ASK_LIMIT_PER_MINUTE` 约束，一次提问最多调一次工具）；部署入口（compose 里配置客户端点和工具清单）。
