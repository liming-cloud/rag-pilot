# D-070 M10 未决问题答复：体检只提示、评测新建上下文、题集可跨库、分块升级后自动重做（2026-11-13，#218、#224、#225）

人对 D-069 之后三个 Issue 的未决问题的答复：

- **#218 资料体检**：
  - 只提示，不拦截入库；“失败”“无分块”沿用现状。
  - 重复文档在**同一租户内跨库**比较：原文件内容哈希相同算“重复”，分块文本重合 ≥ 80% 算“疑似重复”；提示里只列出查看人自己能访问的库，不泄露无权访问的库（D-017）。只做体检提示，不改检索。人问到“同一份文档在多个库、都授权给同一角色时检索会不会变差”：会。检索不按内容去重（RRF 按分块 ID 合并），内容相同的分块重排分也相同，会占掉多条证据（候选 30 → 最多 8 条，D-014），需要综合多段资料的问题受影响；查询耗时基本不变，存储和向量化费用随副本数增加。人定先只提示，由使用者删掉多余的副本。
  - 规则按 D-069 的清单，**去掉 PDF 双栏检测**（只能启发式判断，误标风险最高）；阈值用合成样例和本机试点资料校准后记进实施结论（只记汇总数字）。
- **#224 检索测试与标准题回归**：
  - 权限点 `eval:view`、`eval:manage`、`eval:run`；超级管理员全有，其他内置角色默认都不给。
  - 按**运行人自己的权限**检索（同 D-047 的重新回答），检索过滤仍只在 rag-knowledge 一处（A-05）。
  - 标准题挂在**题集**上，一个题集可以跨多个知识库。查看人无权访问的库里的题**当作不存在**：不显示、不运行、不计分。
  - 期望文档上传新版本时自动接到新版本；文档删除后这道题标为“过期”，不参与运行。
  - **新建上下文**（暂名 rag-evaluation），不改动现有已稳定的功能：新上下文只依赖 answering、knowledge、identity 的 api；answering 的 api 只增加“按运行人权限回答、不写回答记录”的入口，现有接口和行为不变。新增模块按 A-21 记在本条；模块名、依赖方向在实施时补进实施结论并更新架构规则。
- **#225 分块改进**：
  - TableEval 的引用正确率有提升，且合成集、CRUD-RAG、T2Ranking 的召回、引用、拒答都不低于基线（3 轮均值）才合并；某一项下降时由人决定。
  - 升级时**自动把已入库的资料全部重新分块**。全量重新向量化有费用、大库容易被限流，所以 #225 的前置加上 #226（入库限流后按批退避重试）；发布说明写明升级耗时和费用的估算。
