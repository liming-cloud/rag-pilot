# D-063 工具问答评测的实施结论：独立评测类、以审计和模拟服务的记录为准（2026-11-09，#183）

落实 D-056、D-059（人对 #183 的三个未决问题全按推荐答复）：

- **评测类**：`ToolEvaluationRun` 与 `EvaluationRun` 分开（授权设置和观测方式不同），CI 的 `eval` 一次跑两个；评测集 57 题（选择 18、数据与资料冲突 4、无需工具 8、越权 23、注入 4），放 `eval/retail/tools/`，授权设置（直接、经角色、授权后收回、区域）写在同一个文件里。用真实模型选工具，授权判定、令牌、MCP 调用都是真实的，模拟服务 `RetailMcpServer` 作测试代码，不进发布包。
- **口径**：工具选择、参数以 `audit_log` 里该题最后一问的 `DATA_TOOL_CALLED` 为准（工具名、结果=成功、查询条件）；越权调用以模拟服务实际收到的请求数为准——越权题里应为 0，所以拦截发生在我方、没发请求才算过；回答不能带数据引用。前面的铺垫问题（多轮诱导）不计分。
- **结果**（`eval` 3 轮，run 42512937262）：工具选择正确率 100% / 96.3% / 100%，参数正确率 100%，越权调用 0，注入题没有被带偏；回答含期望数值 85.2%～88.9%、无需工具题误调用 0～12.5%（1/8，只报告不设门槛）。
- **评测发现的问题**：第一次运行参数正确率只有 37%，原因是模拟服务的库存工具没有在参数结构里声明 `sku`（对接规范里有），模型不知道参数名；补上后达标。说明参数结构要写全是对接规范的要求，客户系统的工具说明质量直接影响参数正确率，试点时要核对。
- **耗时**：PR 自动跑 1 轮约 19 分钟；手动 3 轮约 55 分钟，`eval` 超时从 60 分钟放宽到 90 分钟。
