# D-072 检索测试与标准题回归的实施结论：放进已有的 rag-evaluation、一道题一个库、三个信号都满足才通过（2026-11-17，#224）

按 D-069、D-070 实施“知识质量”时定下的做法，以及开工后人的答复（2026-11-17）。

- **模块**：没有新建 Maven 模块，放进已有的 rag-evaluation（它本来就是“评测集、评测运行、指标”的上下文，原注释写着“要把结果写入库时再补齐分层”），比 D-070 同意的“新建上下文”范围小。依赖：identity、knowledge、answering、settings 的 `api`，以及原有的 shared、ai（规则卡 A-10 已更新）。settings 不在 D-070 的清单里，运行前的预估费用要用单价表和历史用量，人同意加（2026-11-17）。
- **各上下文 api 新增的内容**（现有接口和行为不变）：
  - answering：`AnswerProbe`，直接用 `AnswerService`（它本来就不写回答记录、不计频率、不进会话），另外交出重排后的前几条资料作为“召回”；为此 `AnswerService` 加了一个带回调的重载，原有入口委托过去。
  - knowledge：`KnowledgeDocuments`（还在的文档、能访问的库里按文件名列文档）和事件 `DocumentReplaced`（新版本就绪、旧版本删除时在同一事务里发出）。
  - settings：`ModelCosts.averageAnswerCost()`，近 30 天“回答 + 备用回答 + 重排”的费用 ÷ 回答次数；没有回答或有没填单价的模型时不估。
  - rag-ai：根包新增能力接口 `UsageAttribution`（把一段工作的模型用量记到指定用途），用途新增 `EVALUATION`；实现是线程上的标记，`applicationTaskExecutor` 经 `TaskDecorator` 继承，流式生成在发起时取定。这是新增的抽象（A-21），理由：验收要求“模型用量里能看到评测用途”，而用量在 rag-ai 内部按调用记，只有在这里打标记才不用改各处调用。
- **一道题在一个知识库里检索**（人定）：期望文档都在这个库里；查看人、运行人不能访问这个库，这道题就当作不存在（D-070）。跨库的问题拆成多道题。题集本身可以跨库。
- **判定**（人定）：应当拒答的题，拒答即通过；期望文档的题，没拒答、召回满足、引用满足才通过，多份文档时按题设的“全部命中 / 任一命中”。“召回”指重排后相关度最高的前几条（条数同送给模型的上限，不论是否达到门槛），“引用”指回答引用的资料所在的文档。结果页分别列出三个信号和没召回的文档。
- **从回答记录、知识缺口转标准题**（人定）：弹窗里“转成标准题”带着问题跳到“试问”，看到当前回答和召回后再选期望文档保存；不改回答记录、知识缺口的接口。
- **运行**：后台逐题串行，跑完一道存一道，页面显示进度；同一个题集同时只能有一次运行（唯一索引）。模型不可用等失败时停下、标为失败，已跑完的题保留；应用重启时把上次没跑完的标为失败，不自动续跑（避免重复花费）。每题的题目、期望存快照，之后改题、删题不影响历史结果；和上一次运行按题目编号对比。
- **期望文档**：上传新版本后经 `DocumentReplaced` 接到新版本（同一事务）；删除后这道题标为“过期”，运行前的预估里列出跳过的题数，运行时不跑。
- **权限点**：`eval:view`、`eval:manage`、`eval:run`，超级管理员全有，内置角色默认都不给（D-070）。知识库和期望文档的选择走评测自己的接口（只列当前账号能访问的库），不要求 `kb:view`。
- **导入**：CSV 由前端解析（和账号导入共用 `lib/csv.ts`，兼容 Excel 存的 GBK），后端按名称在操作人能访问的库里匹配，匹配不上的行跳过并说明原因，其余照常导入，一次最多 500 行。
