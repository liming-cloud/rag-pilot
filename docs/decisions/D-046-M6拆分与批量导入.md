# D-046 M6 拆成接入和运营；账号批量导入、批量上传、资料有效期（2026-11-02）

#124 经人答复：M6 拆成“接入”（#124：账号批量导入、批量上传、资料有效期）和“运营”（#125：知识缺口、运营概览按周查看与导出）两个 Issue，先做接入。其余采纳建议：

- **账号批量导入**：模板是 CSV（不新增依赖），列为用户名、显示名、角色（多个用 `;` 分隔，按角色名匹配）；文件由前端解析（UTF-8 和 Excel 默认的 GBK 都能读），后端只收行。一次最多 500 行；先预检全部行并逐行列出问题，有任何一行有问题就一条都不导；已存在的用户名只报错、不更新。导入人在弹窗里填一个统一初始密码，所有导入的账号首次登录必须先改密码（D-038 的机制），文件里不放密码。同样执行防越权分配；权限 `user:import`。同一批账号的初始密码只算一次 BCrypt 摘要（逐个算 500 行要半分钟），首次登录改密码后各自不同。
- **批量上传**：只改前端，后端接口不变：可以选文件夹（不保留目录层级，跳过 .DS_Store 等系统文件），同时 3 个，一批最多 200 个，结束后汇总“成功 / 重复 / 不支持 / 失败”，可以只重试失败的。不做 zip 上传。
- **有效期的语义**：按文档设生效、失效日期，都可空（空 = 不限，现有文档迁移后都是空，行为不变）；日期按统计时区（`rag.settings.stats-zone`）解释，失效日期当天仍有效，次日起不参与检索，未生效的同样不参与。过滤写在 rag-knowledge 检索 SQL 里、与权限过滤在同一处（`ChunkSearchMapper.xml` 的 `currentDocuments`），问答、追问、重新回答都经过它；历史回答里引用的原文仍可查看（审计）。上传新版本不传失效日期时继承旧版本的。为读统计时区，rag-knowledge 依赖 rag-settings 的 api 包（`AnsweringSettings`），不新增外部依赖；settings 不依赖 knowledge，不成环。
- **权限与提醒**：新增权限点 `doc:update`（修改资料信息），内置“管理员”默认有，迁移时给还有 `doc:upload` 的内置“管理员”加上；上传时顺带设有效期用 `doc:upload`、`doc:replace`。提醒只在站内：文档列表和知识库列表显示“即将到期 / 已失效”并能筛选，运营概览显示数量；提前天数是部署配置 `rag.knowledge.expiry-warning-days`（`RAG_EXPIRY_WARNING_DAYS`，默认 30，1 到 365，非法值启动失败）。不发邮件或 IM。
- **评测**：合成集加一份已失效的旧版制度（内容与现行版冲突）和一份下月才生效的新规（`corpus/validity.json` 设有效期，评测脚本上传时带上），加 3 道题；报告新增“检索或引用过期资料”，与越权泄漏一样必须为 0。只加题，不删、不放宽现有题。
