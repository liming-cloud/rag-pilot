# D-061 数据范围授权的实施结论：内核用“站点”、整体替换授权、主数据取不到时只拒绝（2026-11-08，#181）

落实 D-056、D-059（人对 #181 的三个未决问题全按推荐答复），实施中定的几点：

- **内核不写“门店”**：`KernelNeutralityTest` 禁止内核代码出现行业包的标志词（D-045），所以 rag-data 和管理页统一叫“站点”（代码里 `unit`），“门店”只出现在客户系统的工具协议字段（`store_id`）和测试示例数据里。管理页的文案以后要按行业包显示“门店 / 网点”时，再把名称放进行业包（本次不做，未触及“先停下来问人”事项）。
- **新增上下文 rag-data，依赖 identity**：AGENTS.md“上下文依赖”已补；#182 起 answering 经 `DataAccess`（rag-data 的 api）判定每次工具调用。判定只在 `DataScopeService` 一处，不看是不是管理员。
- **授权整体替换**：管理页保存时把角色或账号的工具、站点、区域整体提交，请求里没有的就是收回；增加和收回分别记一条审计（`DATA_GRANTED`、`DATA_REVOKED`），一次授权没有变化不记；会收回授权时页面先确认。
- **判定语义**：用户本人 ∪ 所属角色取并集（D-059）；参数里指定的站点、区域必须全部在范围内，有一个不在就整体拒绝，不悄悄缩小；指定了但主数据里查不到的区域也拒绝，不当作没有限定。
- **主数据取不到时只拒绝**：区域授权展开不出站点、按没有处理（直接授权的站点仍有效），只会少放行，不会多放行；授权页提示稍后再试，已有授权不受影响。
- **主数据来源与缓存**：经 rag-ai 的 `ToolCaller` 调客户的 `list_stores`，用 rag-cache 缓存，客户系统里门店变了最多滞后一个缓存过期时间；可授权的工具清单来自部署配置 `rag.data.tools`，不存库（工具能不能调只由授权决定，D-058）。
