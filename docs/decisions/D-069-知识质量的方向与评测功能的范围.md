# D-069 知识质量的方向与评测功能的范围：先资料体检、再标准题回归，不做自动出题（2026-11-13）

人工测试时提出：平台要不要给使用者一个评测功能，上传资料后对知识库做一次评测，用来判断换模型、改资料的效果，并指导使用者整理资料。查了同类产品和公开研究后，人的决定：

- **新里程碑 M10 知识质量（1.x）**，分三个结果，按顺序做：资料体检（#218）→ 检索测试与标准题回归（#224）→ 分块改进（#225）。体检排在 OCR（#223）之前：体检能先给出有多少文档、多少图片需要 OCR，作为选方案的依据。
- **资料体检不调模型**：把 `parse-check.sql` 的规则产品化到文档列表，每篇文档给出结论和一句整改建议；入库时算好信号存进 `document`，页面和 `parse-check.sql` 读同一份结果，规则只写一处。原 #218（只给 `parse-check.sh` 加“疑似内容在图片里”）并入体检，因为改的是同一批代码。体检用现有的 `kb:view`，不新增权限点。现有规则要先补的：PDF 解析本身不出标题，要和“文档没写标题”分开提示；双栏 PDF 和截图为主的文档没被标出；1%、40%、5 块三个阈值要校准。
- **标准题回归不用评判模型**：只看系统自己能确定的信号——有没有拒答、有没有召回期望文档、引用里有没有期望文档。标准题存期望的**文档**，不存分块 ID，重新分块后不失效（RAGFlow 评测功能请求 infiniflow/ragflow#15033 里的教训）。做法参照 Dify 的检索测试、标准题和坏例。新增 `eval:*` 权限点（具体清单在 #224 的未决问题里）。
- **费用先不设上限**：运行前按单价表（D-065）显示预估费用，用量在“模型用量”里单独记为评测用途，由人自己控制。
- **自动出题先不做**：公开研究显示，从分块生成的合成问题比真实问题简单，会系统性高估绝对分数，只适合比较不同的检索配置（Rahmani 等，[arXiv 2405.07767](https://arxiv.org/abs/2405.07767)）；标准题以真实问题为准，来源是手写、CSV 导入、“回答记录”和“知识缺口”。对照参考答案的正确性评判（`AnswerJudge` 进产品）也以后再议。
- **分块改进排在标准题之后**：表格每块带表头和章节，分块参数（第一版定的 500 / 80）用评测对比选定，改动按 D-068 要在合成集和开源集上同样成立。
- **文档级权限暂不做**：现在权限只到“知识库 × 用户 / 角色”（D-017、D-041）。人定试点阶段不做文档级授权，需要时先把敏感文档放进单独的知识库；有需求时再规划，记在 ROADMAP 待办。
