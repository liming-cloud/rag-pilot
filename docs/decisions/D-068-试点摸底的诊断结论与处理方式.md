# D-068 试点摸底的诊断结论与处理方式：本机部署验证、pptx 与 OCR 另开 Issue、旧版 .doc 丢弃（2026-11-11）

#134 拿到客户资料后的决定，修订 D-055 的第一条：

- **在本机部署验证**：人答复客户已同意，资料放在我们的一台机器上（仓库外的目录），用 v1.0.0.1 离线包在本机 Docker 里部署、导入、核对和评测，代替“只在客户服务器上做”。其余不变：资料、问题、评测报告原文不进代码仓库、CI、Issue 和 PR（仓库是公开的），Issue 里只记汇总数字和脱敏后的类型；试点结束按客户要求删除。本机部署不算 #129 的“干净 Linux 服务器演练”。
- **标注由人确认**：评测题由我们按资料起草（预期文档、答案关键词），人作为业务确认人逐题确认后计入指标（#134 第 4 条）。资料包里标为“部分依据 / 仅相关背景”的真实咨询答案边界不清，先不计入，等业务给出现行答案。
- **草稿基线不改标注，改进只做通用能力**：评测后发现 3 道题系统答对了、是标注太窄判成错，人定不改标注、就用这一版作基线。人定的方向：**不针对这批客户资料做专门调优**（不为某份资料改提示词、同义词、门槛），要做的是提升系统本身的准确性，改动要在合成集和开源集上同样成立。
- **pptx**：客户资料里 pptx 课件占三成，现在直接拒收。另开 #217，用现有 poi-ooxml 的 XSLF 取文字，不新增依赖；不在 #134 里做。
- **OCR（#134 第 7 条）**：没有纯扫描件，但有几份操作手册的内容主要在截图里。OCR 不在 #134 里做，另开 #218 再选方案；D-019 暂不修订。
- **旧版 .doc（#134 第 8 条）**：只有 1 份，是过期的培训通知，丢弃，不加 `poi-scratchpad`；系统继续拒收 .doc 并提示另存为 .docx。
- **评测等待入库的上限**：`EvaluationRun` 原来按“每篇 3 秒、至少 90 秒”等入库，客户的一张大表格就有几千块，等不及；改为再按语料大小每 MB 加 60 秒。
- **部署脚本兼容 macOS 的 bash 3.2**：在本机演练时 `build.sh` 因 `$变量` 后紧跟中文字符而失败；脚本里这种写法改为 `${变量}`，`DeployScriptsTest` 检查。服务器仍以 Linux 为准（D-048）。
