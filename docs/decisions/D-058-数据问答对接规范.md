# D-058 数据问答对接规范：MCP Streamable HTTP、我方签发短期令牌、数据范围由我方判定（2026-11-07，#166）

规范正文在 [`docs/integration/mcp-tools.md`](../integration/mcp-tools.md)，这里只记决定和理由（落实 D-056 对 #166 的答复）：

- **传输**：MCP Streamable HTTP，以 2026-07-28 版为准（无会话、请求自带版本元数据），兼容 2025-11-25；不用 stdio。我方 client 用 Spring AI 2.0 的 MCP client，不自己写协议，只在 rag-ai 引用（#168）。
- **身份**：每次调用我方签发 ≤ 60 秒的 JWT（受众为该 MCP 端点、绑定工具名、带 `jti`），客户系统只校验签名。这是对 MCP 授权规范（OAuth 发现与动态注册）的有意简化：服务端到服务端、线下预配置信任，仍遵守受众校验、令牌放头里、不透传。
- **数据范围（权限语义）**：门店 / 区域维度，授权对象沿用用户或角色，与知识库授权同一套模型，判定只写在我方一处，管理员不绕过；调用前、令牌、返回后三道检查。
- **只读**：1.x 只接只读工具；是否只读由我方工具授权清单决定，客户端工具注解只作提示（规范要求把注解视为不可信）。
- **引用与审计**：回答带来源、查询条件、数据截至时间；审计保留 1 年，记业务条件和行数，不记令牌、返回内容、问题原文。
- 超时 10 秒、重试 1 次、每用户 30 次/分钟等数值是起始值，试点后按实测调整。
- 规范与实现不一致处（如 Spring AI 支持的协议版本、每次调用令牌的注入方式）在 #168 开工时验证，改动写回规范文档。（#168 已拆为 #180～#183，验证在 #180。）
